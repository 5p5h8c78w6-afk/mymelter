# MyMelter PWA 1.8.1

## 1.8.1 — iPhone再生開始と長尺動画の根本修正（2026-10-27）

- 動画一覧の「直接再生〇件」という誤解を招く表示を、「再生URL検出〇件（実再生は別途確認）」に変更しました。
- **45秒を超えるだけで再生元srcを解除する処理を廃止。** 以前は`loadedmetadata`後に長尺用プレースホルダーへ移り、動画の読み込みと再生が中断され得ました。長尺動画も通常の`video playsinline`で保持します。
- **サムネイルをタップした同一イベント内**で動画フィードを表示・アクティブ化し、`video.play()`を開始します。従来は`requestAnimationFrame`の2段待ち後に初期化され、iPhone Safariのユーザー操作を失う可能性がありました。
- `playsinline`、`webkit-playsinline`、ミュートを維持し、音声は既存UIからON/OFFできます。Safariが再生を許可しない場合は従来どおりタップ再試行を案内します。
- 再生失敗時だけ、**配信ドメイン・ファイル形式・選択した再生経路・MediaError番号・readyState**を表示し、診断を端末でコピーできるようにしました。完全な動画URL、クエリパラメータ、秘密トークンを診断文に含めません。
- 失敗時は「再試行」「Safariで動画URLを開く」「元ページで確認」を用意。通常時には余計な確認画面を挟みません。
- Safari取り込みブックマークレットは **v28のまま**です。今回はSafariブックマークの変更やホーム画面アイコンの再登録は不要です。
- 1.8.0までのチャンネル、保存済み、履歴、記事・画像Reader、Worker 1.3、HLS代替経路を保持。
- 単体37/37・Chromiumブラウザ回帰（同一タップ内の再生呼び出し、120秒のsrc保持、URLトークン非表示）PASS。**iPhone Safari実機、実サイトでの動画再生は未確認**です。
- 元サイトの公開条件、アクセス制限、DRMは回避しません。自動テストと実再生を混同しません。



## 1.8.0 — ワンタップ動画再生・アーカイブ件数拡大・形式フォールバック

- **サムネイルのタップで動画フィードへ直接移動**。前版の余計な「動画を確認」「再生する」確認ダイアログは通常フローから撤去。既存動画URLがあれば直ちに再生を試します。
- 実動画URLのない候補も動画フィードに残し、サムネイルと「元ページで再生する」を明示します。URLを捏造しません。
- 動画が再生できなかったときは、削除済みと決めつけず「配信元制限・期限切れ・形式非対応など」を案内します。
- Safari取り込み **v28** では `twi-dl.net/hozon.php` の「次のページへ」を同一オリジンで追い、最大4ページ・最大120候補をまとめます。ページ取得に失敗した場合は収集済みの候補を保持します。
- 動画詳細確認は最大40件（前版12件）まで拡大。**MP4が明示されていればHLSより優先**し、両方見つかった場合は別形式のHLSリンクを予備に保持します。再生がエラーならHLSを一度試します。
- `videoUrl`検出は再生成功の証拠ではありません。iPhone実機での再生、サーバーによるReferer制限や期限切れ動画などは別途確認が必要です。
- 大量DOMでの速度・メモリを抑えるため、無制限の900件一括取得は行いません。現在の上限は**1回120候補**です。
- 保存済みデータ、Worker 1.3、正式旧版、画像・記事の閲覧動作を保護します。
- Safariのブックマークレットはv28に**一度更新が必要**。ホーム画面のPWAアイコンは従来のまま利用します。



## 1.7.9 — Safariで取得した動画の詳細情報をMyMelterへ渡す

- Safari軽量取り込みをv27へ更新。旧v26のサムネイル/リンク抽出を保ち、**同じサイト内の動画詳細ページ**を最大12件まで、4件並列・1件約3.2秒の上限付きで取得し、MP4/HLSの実URLを抽出します。
- Safari上では「動画を確認中 進行数/対象数（取得件数）」を表示。完了後、確認成功件数をMyMelterチャンネルに表示します。失敗した動画もリンクだけの候補として残します。
- 対象サイトへの既存の閲覧権限がある場合のみ動作します。ログイン・403/451・CORS・DRMの回避は行いません。
- GitHub Pages PWAから動画詳細ページを直接取得できない場合に備え、取り込む**前の同一オリジン上**で動画ファイルURLを取得する設計です。
- 同じURLで再取り込みしたチャンネルの既存データを保護。サムネイルが消える問題を再発させず、動画URLが確認できなければ元ページボタンを保持します。
- Chromiumの擬似HTMLで動画詳細のMP4/HLS成功2件と403等失敗2件を検証。実際のtwi-dl.netおよびiPhone Safariは未検証です。
- Safariブックマークは **v27へ1回差し替え** が必要です。アプリ本体は従来のホーム画面アイコンで自動更新できます。



## 1.7.8 — 動画サムネイルが消える問題と再生確認UI

- 動画候補のサムネイルをタップすると、一覧を描き直さずに動画確認ダイアログを即時表示。元のサムネイルを表示したまま詳細ページの動画URLを確認します。
- 詳細ページの取得が成功して動画URL候補が見つかった場合、自動では画面を切り替えず、明示的な「再生する」タップで既存動画フィードへ進みます。iPhone Safariでのユーザー操作制限への対応です。
- 直接動画が見つからない場合は、候補ゼロ、HTTP 403等の取得制限、取得失敗を区別して表示し、「元ページを開く」「再確認」を残します。
- 旧Safari取込データで `twi-dl.net/v.php?video=...` が画像扱いで保存されている場合は、既存データを壊さずに動画候補として表示・操作します。
- サムネイル横の複数操作ボタンが小さな画面で重ならないようレイアウトを調整します。
- Safari取り込みコードは **v26のまま**。すでにv26へ差し替えてある場合、ブックマークの更新は不要です。アプリを開き直すだけで新しいアプリコードが配信されます。
- MP4/HLSのURLが見つかってもその配信が実際に成功する保証はありません。取得元がアクセスを制限する場合は回避せず元ページでの確認を案内します。
- 単体・Chromium合成HTMLテストで新動作を検証。実サイトでの動画再生とiPhone Safari実機操作は PENDING です。



## 1.7.7 — Safari「無反応」の構造対策

- Safariの通常取込を短い**v26即時起動版**に置き換えました。旧v25は約28,000文字で複数ページ取得と待機が続き、操作しても反応が見えない問題がありました。
- v26は約5,900文字。ブックマークから起動直後にページ上へ青い「MyMelter：ページを確認中…」表示を出し、**開いているページのDOMのみ**を抽出します。ネットワークページ巡回を行わず、候補数を表示してMyMelterに戻ります。
- 候補ゼロでも「取込コードは起動しましたが、候補が見つかりません」と明示します。まったく何も表示されない場合は、SafariがブックマークのJavaScriptを実行していない、またはサイト側CSPなどの制限が考えられます。
- 動画詳細URLがあるだけのカードは動画候補として一覧に残し、MyMelter内の「動画を確認」から実際に存在する動画ファイルの再取得を試みます。サイトの認証・DRM・HTTP制限は回避しません。
- 旧v25の詳細抽出器は`buildBrowserImportBookmarkletAdvanced`としてコード内に保持します（通常取込はv26）。長いブックマークへの復帰は行いません。
- **一度だけ**Safari側の「MyMelter取込」ブックマークURLをv26で上書きする必要があります。ホーム画面のMyMelterアイコンと保存データは保持します。
- Chromiumの合成HTMLで起動表示・候補検出・移動・候補ゼロの警告を検証。iPhone Safariおよび実サイトtwi-dl.netでの最終確認は未実施です。

- 取得先サイトの403/451/認証やDRMを回避する実装ではありません。実サイトとiPhone Safariの最終実操作検証は未確認のままです。

## GitHub Pagesへ載せる

1. GitHubで公開リポジトリを作成します（例: `mymelter`）。
2. このフォルダの**中身**をリポジトリ直下へアップロードします。
   - `index.html` がリポジトリ直下にある状態にしてください。
3. GitHubの `Settings` → `Pages`。
4. `Deploy from a branch` → `main` → `/(root)` → `Save`。
5. 表示された `https://ユーザー名.github.io/mymelter/` をiPhoneのSafariで開きます。
6. Safariの共有 → `ホーム画面に追加`。

## CORSでサイト解析できない場合

ブラウザにはCORS制限があります。GitHub Pagesから直接読めないサイトを自動解析したい場合は、`worker/worker.js` をCloudflare Workers無料枠へ配置できます。

推奨設定:
1. Cloudflare WorkersでWorkerを1個作成。
2. `worker/worker.js` を配置。
3. Workerの環境変数 `MYMELTER_KEY` に長いランダム文字列を設定。
4. MyMelter → 設定 → Cloudflare Worker URL にWorker URLを入力。
5. MyMelter → 設定 → Workerキー に同じキーを入力。
6. 取得モードを「自動（直接 → Worker）」にします。

WorkerはGETのみで、Cookieを転送せず、ローカル/プライベート宛先を基本的に拒否します。

### Worker 1.1 の403診断
- 通常ブラウザ互換の Accept / Accept-Language / User-Agent で取得します。
- Workerキー不一致、Worker安全ブロック、取得先サイトのHTTP 403/429をMyMelter側で区別して表示します。
- 取得先が403を返した場合でもCAPTCHA・Cookie・認証・IP制限の回避は行いません。
- `https://www.twidouga.net/jp/ranking` が取得先403になった場合だけ、公開されている実ページ `https://www.twidouga.net/jp/ranking_t1.php` を1回だけ自動で試します。
- 代替URLも403なら「サイト側がWorker経由アクセスを拒否」として停止します。

## Safari取り込み（Worker 403サイト）

Worker接続自体が正常でも取得先サイトがHTTP 403を返す場合は、Safariで実際に表示したページからローカル取込できます。

1. MyMelter → 設定 →「取込ブックマークを準備」
2. 「取込コードをコピー」
3. Safariで任意ページをブックマークし、名前を「MyMelter取込」、ブックマークURLをコピーしたコードに置換
4. 対象ページをSafariで開く
5. ブックマーク「MyMelter取込」を実行
6. MyMelterへ戻り、取得した項目をローカルのスナップショットチャンネルとして保存

この方式はWorker/IP経由の取得ではなく、Safari上でユーザーが表示できたDOMから公開リンク・画像・動画候補を抽出します。twidougaではv8取込を使い、1〜10位と11〜20位を同じチャンネルへ統合し、DOMで正しく対応付けた動画を優先して取り込みます。1〜10位と11〜20位を同一チャンネルへまとめ、取り込めた全動画をそのまま連続スワイプ再生できます。1〜10位ページに加えて11〜20位ページも同一オリジンで自動取得します。正規表現リテラルを使わずSafariブックマークURLで崩れにくい方式に変更し、`video.twimg.com` の直接動画URLを優先して候補化します。再生時は設定済みWorkerをメディアストリーミング用に使い、Range要求を転送します。Worker再生が失敗した場合は直URLを1回試します。既存の「MyMelter取込」ブックマークはv3コードへ1回更新してください。ログイン回避、CAPTCHA回避、DRM回避は行いません。

## Appleショートカット保存

MyMelter → 設定 →「Appleショートカットを使う」をONにすると、端末保存ボタンから `MyMelter保存` ショートカットへURLを渡せます。

ショートカット側は概ね以下の構成です。
1. ショートカット入力を受け取る
2. URLの内容を取得
3. 写真アルバムに保存

DRM、アクセス制限、認証回避は対象外です。自分に保存権限がある通常のメディアで使ってください。

## 対応範囲について

MyMelterは公開HTML、RSS/Atom、通常の画像/動画URLを中心に扱います。以下はサイトごとに制限される場合があります。
- ログイン必須コンテンツ
- JavaScriptを実行しないとHTMLに現れない一覧
- 強いBot対策
- DRM動画
- Cookie/認証トークンが必要なメディア

この場合でも、チャンネルを元サイトへのランチャーとして登録できます。
